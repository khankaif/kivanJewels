# UX & CX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the ERP feel faster and more trustworthy to operate than the spreadsheet it replaces, without giving up any of the integrity guarantees already built.

**Architecture:** No new runtime. Everything here is presentation and interaction on top of the existing feature-sliced structure: server components keep owning data, `sonner` carries action feedback, URL search params keep owning filter state, and route-segment files (`loading.tsx`, `error.tsx`) carry pending and failure states.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4, shadcn/ui on Base UI, `sonner` (installed), `cmdk` (to add for the command palette).

**Spec:** This document. Findings below were measured in the codebase on 2026-08-28, not assumed.

---

## What is actually wrong (verified, not guessed)

| Finding | Evidence | Cost to the user |
|---|---|---|
| **Every successful action is silent** | `sonner` is installed and `components/ui/sonner.tsx` exists, but no `<Toaster />` is mounted and `toast()` is called nowhere. Actions return `{ ok: "..." }` that nothing displays. | You record a ₹6 L payment and get no confirmation. The only signal is a dialog closing. |
| **No pending or failure states** | Zero `loading.tsx`, `error.tsx`, `not-found.tsx` files in `app/`. `Skeleton` is installed and unused. | A slow query looks like a frozen app; a failed one is a white screen. |
| **No column sorting** | No sort handling in any page under `app/(app)/`. | The spreadsheet sorts every column. This is the single most-missed Excel behaviour. |
| **Dates render as raw ISO** | `{b.billedOn}`, `{m.movedOn}` print `2024-11-14`. | Indian trade reads `14-11-2024` or `14 Nov 2024`. ISO reads as a foreign format. |
| **No totals row on registers** | Registers show filtered aggregates in a header strip, not aligned under their columns. | The source sheet literally carries a totals row (row 1 of the CSV export). Column-aligned totals are how the numbers get checked. |
| **No global search** | No `cmdk`, no keyboard handler. | Finding bill `KJ/25-26/L045` means navigating, filtering, typing. |
| **Filters lost on navigation** | Filter state lives only in the URL of the page you are on. | Drilling into a bill and coming back loses the filter. |
| **Tables overflow on mobile** | 10 files wrap tables in `overflow-x-auto`. | Horizontal scrolling a 9-column table on a phone is unusable in a trading office. |

---

## Global Constraints

- **No client-side data fetching.** Server components stay the data owner. Interactivity is URL state plus small client islands.
- **Filter state stays in the URL.** Every view must remain bookmarkable and shareable, and the CSV export reuses the same query string.
- **Never colour by raw palette.** Use `text-positive` / `text-negative` / `text-warning` and the surface variants. The brand primary sits at oklch hue 162; money signals are hue-separated on purpose.
- **Money and carats always `tabular-nums` and right-aligned.** Columns of numbers must be scannable.
- **No feature may weaken an invariant.** The overdraw guard, append-only ledgers and reconciliation gate are not negotiable for UI convenience.
- **Every new interactive control needs a keyboard path and an accessible name.**

```tsx
// features/shared/components/action-toast.tsx
'use client';

import { useEffect, useRef } from 'react';
import { toast } from 'sonner';

type State = { error: string } | { ok: string } | null;

/** Fires exactly once per distinct action result, including repeats. */
export function useActionToast(state: State) {
  const seen = useRef<State>(null);
  useEffect(() => {
    if (!state || state === seen.current) return;
    seen.current = state;
    if ('ok' in state) toast.success(state.ok);
    else toast.error(state.error);
  }, [state]);
}
```

- [ ] **Step 3: Use it in every dialog**

In each dialog, after the `useActionState` call:


Keep the inline `<p role="alert">` for errors as well: a toast is transient, and a validation error must stay readable while the user fixes the field.

### Task 2: Indian formatting

**Files:**
- Modify: `lib/format.ts`
- Modify: every page rendering a date

**Interfaces:**
- Produces: `date(iso: string | null): string` → `14 Nov 2024`; `dateShort(iso)` → `14-11-2024`; `days(n)` → `12d`.

- [ ] **Step 1: Extend the formatter**

```ts
// lib/format.ts
const MONTHS = ['Jan','Feb','Mar','Apr','May','Jun','Jul','Aug','Sep','Oct','Nov','Dec'];

/** ISO YYYY-MM-DD -> "14 Nov 2024". Parsed by hand: a calendar date has no
 *  time zone, and `new Date(iso)` would reintroduce one. */
export function date(iso: string | null | undefined): string {
  if (!iso) return '—';
  const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(iso);
  if (!m) return iso;
  return `${Number(m[3])} ${MONTHS[Number(m[2]) - 1]} ${m[1]}`;
}

export const dateShort = (iso: string | null | undefined): string => {
  if (!iso) return '—';
  const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(iso);
  return m ? `${m[3]}-${m[2]}-${m[1]}` : iso;
};
```

Do **not** use `toLocaleDateString` with a `Date`: constructing a `Date` from an
ISO date string reintroduces the timezone bug already fixed in the read model,
where IST rendered every date one day early.

- [ ] **Step 2: Apply it**

Replace `{b.billedOn ?? '—'}` with `{date(b.billedOn)}` across `app/(app)/bills/page.tsx`, `bills/[key]/page.tsx`, `movements/page.tsx`, `ledger/page.tsx`, `parties/[id]/page.tsx`, and `features/memos/components/memo-list.tsx`.

- [ ] **Step 3: Add a unit test**

```ts
// tests/format.test.ts
import { test } from 'node:test';
import assert from 'node:assert/strict';
import { date, dateShort } from '../lib/format';

test('formats ISO dates without touching time zones', () => {
  assert.equal(date('2024-11-14'), '14 Nov 2024');
  assert.equal(dateShort('2024-11-14'), '14-11-2024');
  assert.equal(date(null), '—');
});
```

Run: `npx tsx --test tests/format.test.ts` — expect 1 pass.

- [ ] **Step 1: The header control**

```tsx
// components/layout/sortable-head.tsx
import Link from 'next/link';
import { TableHead } from '@/components/ui/table';

export function SortableHead({
  column, label, params, align = 'left',
}: {
  column: string; label: string;
  params: Record<string, string | undefined>;
  align?: 'left' | 'right';
}) {
  const active = params.sort === column;
  const nextDir = active && params.dir === 'desc' ? 'asc' : 'desc';
  const qs = new URLSearchParams(
    Object.entries({ ...params, sort: column, dir: nextDir, page: '1' })
      .filter(([, v]) => v) as [string, string][],
  );
  return (
    <TableHead className={align === 'right' ? 'text-right' : undefined}>
      <Link href={`?${qs}`} className="inline-flex items-center gap-1 hover:underline">
        {label}
        <span aria-hidden className={active ? 'opacity-100' : 'opacity-30'}>
          {active && params.dir === 'asc' ? '↑' : '↓'}
        </span>
        <span className="sr-only">
          {active ? `sorted ${params.dir === 'asc' ? 'ascending' : 'descending'}` : 'sort by this column'}
        </span>
      </Link>
    </TableHead>
  );
}
```

- [ ] **Step 2: Whitelist sort columns in each query**

Never interpolate a user-supplied column into SQL. In `getBills`:


```ts
// app/api/search/route.ts
import { auth } from '@/lib/auth/server';
import { sql } from '@/db/client';

export async function GET(req: Request) {
  const { data: session } = await auth.getSession();
  if (!session?.user) return Response.json({ results: [] }, { status: 401 });

  const q = new URL(req.url).searchParams.get('q')?.trim();
  if (!q || q.length < 2) return Response.json({ results: [] });
  const like = `%${q}%`;

  const [bills, parties, lots] = await Promise.all([
    sql`SELECT bill_key, bill_no, direction, party_name, gross FROM bills
        WHERE bill_no ILIKE ${like} ORDER BY billed_on DESC LIMIT 5`,
    sql`SELECT id, name FROM parties WHERE name ILIKE ${like} ORDER BY name LIMIT 5`,
    sql`SELECT lot_no, stone_type, balance FROM lot_balances
        WHERE lot_no ILIKE ${like} ORDER BY balance DESC LIMIT 5`,
  ]);

  return Response.json({
    results: [
      ...bills.map((b: any) => ({
        group: 'Bills', label: b.bill_no, hint: b.party_name,
        href: `/bills/${encodeURIComponent(b.bill_key)}?direction=${b.direction}`,
      })),
      ...parties.map((p: any) => ({ group: 'Parties', label: p.name, href: `/parties/${p.id}` })),
      ...lots.map((l: any) => ({
        group: 'Lots', label: l.lot_no, hint: l.stone_type,
        href: `/stock/${encodeURIComponent(l.lot_no)}`,
      })),
    ],
  });
}
```

## Deliberately not in this plan

- **A charting library.** The dashboard's job is "what needs acting on today". Trend charts are a reporting concern; add them when someone asks a question a table cannot answer.
- **Optimistic UI.** Every mutation here is money or stock. A confirmed write is worth the round trip.
- **A design system of our own.** shadcn plus the theme tokens is the system. Component variants get added when a second use appears, not before.
- **Dark-mode toggle.** The theme ships both; the OS preference already drives it. Add a toggle when someone asks.
